# Landing Page Designer — AI B2B SaaS

Design and build high-converting, visually distinctive landing pages for AI B2B SaaS products. Works with any stack and CSS approach — React, Next.js, plain HTML, Tailwind, CSS modules, whatever the project uses.

The design references below are not templates to copy. They are examples of what good, considered B2B SaaS design looks like — studied to extract the specific decisions that make them feel real and non-generic. Use this knowledge to inform every design choice: typography pairing, color discipline, layout rhythm, copy voice, and component detail. The goal is output that looks like it was designed by someone with taste, not generated by an AI defaulting to safe choices.

---

## Design References

These three references were studied and built as working mockups. Their patterns, decisions, and constraints are documented below as a knowledge base — not a menu to pick from.

### 1. Forge (Dark editorial)

**When to use:** Dev tools, infrastructure, PLG products, technical/engineering audiences.

**Reference file:** `forge-landing.html`

**Palette:**
- Background: `#0a0a0a`
- Primary text: `#ffffff` / `#e4e4e7`
- Body/secondary: `#a1a1aa` (contrast 7.0:1 on `#0a0a0a` ✓)
- Meta/labels: `#8c8c96` (contrast 5.3:1 on `#0a0a0a` ✓)
- App chrome: `#111112`
- Borders: `rgba(255,255,255,0.08)`
- Accent: gradient purple→blue (`#a78bfa` → `#60a5fa`)

**Typography:** Inter — H1 60px/600, −0.04em tracking. Headlines left-aligned. Never centered.

**Key patterns:**
- **Nav:** Sticky `#0a0a0a`. Logo icon + name left · nav links center in `#a1a1aa` · `Log in` text + white pill `Sign up` right
- **Hero:** No announcement badge. H1 left-aligned, max-width ~960px. Subtext left + `New  Feature →` on the same row, right-aligned. Product UI mockup bleeds to page edges, no bottom border — flows straight into next section.
- **Product mockup:** Full app chrome (traffic light dots + URL bar), sidebar + main content, built entirely in HTML/SVG. No placeholder images.
- **Feature section:** 52px headline left · body + `→ numbered link` right. `[01] SECTION LABEL` in small caps above headline.
- **FIG pillars:** 3-col with `FIG 0.1` / `FIG 0.2` / `FIG 0.3` labels. Isometric wireframe SVG illustration per column. Vertical `1px rgba(255,255,255,0.08)` dividers.
- **Testimonials:** 2 large cards in distinct saturated colors (e.g. lavender `#c4b5fd` bg, yellow `#fef08a` bg). Company initials as oversized watermark behind quote. High contrast dark text on each.
- **Metrics:** 3-col, 60px numbers, `1px` vertical dividers.
- **CTA:** Centered 72px headline. Two pill buttons: white filled + outlined.
- **Footer:** Logo icon only (no wordmark) + 5 link columns + minimal bottom bar with legal links.

### 2. Relay (Warm light, technical-editorial)

**When to use:** API/developer products, workflow automation, agent infrastructure, teams that ship fast.

**Reference file:** `relay-landing.html`

**Palette:**
- Background: `#f0eeeb` (warm off-white)
- Text: `#1a1a1a`
- Body: `#666` (contrast 5.7:1 on `#f0eeeb` ✓)
- Accent: `#5B5BD6` indigo-purple
- Card bg: `#f8f7f4`
- Borders: `rgba(0,0,0,0.08)`

**Typography:**
- **Headlines:** Crimson Pro (serif), `font-weight:400` (light). Italic on key words: *teams*, *agents*, *speed*. Load via Google Fonts: `family=Crimson+Pro:ital,wght@0,400;1,400`
- **Body/UI:** Geist sans-serif. Load via Google Fonts: `family=Geist:wght@400;500;600;700`
- **Nav, buttons, labels, code:** Geist Mono. Load via Google Fonts: `family=Geist+Mono:wght@400;500`. Apply with `nav a, nav span { font-family: 'Geist Mono', monospace }` and `a[style*="padding"] { font-family: 'Geist Mono', monospace }`
- **Stats:** Large Geist figures, `font-weight:600`

**Key patterns:**
- **Nav:** `*` asterisk SVG icon + Geist Mono all-caps brand name left · nav links Geist Mono all-caps center · `Log in` + indigo pill `Sign up` right. Sticky `#f0eeeb` bg, `1px` bottom border.
- **Section labels:** `#01 — Section Name` in Geist Mono uppercase `#5B5BD6`. Always precedes H2.
- **Hero:** Centered. Crimson Pro serif H1 (~84px, weight 300–400) with italic key words. Illustrated or pixel-art background. Subtext centered 17px. Two sharp-cornered buttons: `1.5px` border outline + indigo filled. **No rounded corners anywhere.**
- **Feature list:** Left col = section label + serif H2 + rows separated by `1px rgba(0,0,0,0.08)` lines. Each row: 32×32 outline icon box + Geist Mono uppercase label + Geist body. Right col = code window or product screenshot.
- **Code window:** Traffic light dots + language tab sidebar (active tab `#5B5BD6`). Syntax: green for strings, purple for URLs.
- **Integration grid:** 2-col, `1px` border lines. Each cell: logo + Geist Mono uppercase name + `↗` right-aligned.
- **Testimonials:** 3-col separated by `1px` dividers. Crimson Pro italic 16px quote. Round avatar + Geist Mono caps name + company.
- **CTA:** Crimson Pro serif H2 (64px/400), centered. Indigo filled + outline dark sharp-cornered buttons.
- **Footer:** `*` icon + Geist Mono all-caps wordmark. Geist Mono footer links.

### 3. Vela (Clean white, refined, enterprise)

**When to use:** Fintech, enterprise SaaS, ops/analytics tools, CFO/COO-level buyers. Aspirational, trustworthy, polished.

**Reference file:** `vela-landing.html`

**Palette:**
- Background: `#ffffff`
- Headings: `#1a0a2e` (dark purple)
- Body: `#666` (contrast 5.7:1 on `#fff` ✓)
- Secondary: `#888` (contrast 4.6:1 on `#fff` ✓)
- Card bg: `#f7f6f4` / `#ebebea`
- Accent dot: `#c8ff00` lime
- Section pill bg: `#f0eef7`
- Borders: `rgba(0,0,0,0.08)` – `rgba(0,0,0,0.1)`

**Typography:** DM Sans (approximates GT America) — Regular 400, Medium 500, Semibold 600 for hero H1 only. Tracking −0.03em to −0.04em on H1/H2. Load: `family=DM+Sans:ital,opsz,wght@0,9..40,400;0,9..40,500;0,9..40,600`

**Key patterns:**
- **Nav:** Small logo mark + brand name left · 4 nav links center in `#555` · Black pill `Schedule a demo` right. Sticky with `backdrop-filter:blur(12px)` + `1px` bottom border.
- **Hero:** Clean white, no illustration. `+` corner markers in `#ddd` at each corner of the hero area. Small centered announcement bar: `1px` border, colored badge pill + text + dark filled arrow button (sharp corners). H1 88px/700, centered, `#1a0a2e`, `−0.04em` tracking — let the type do all the work. Optionally one word gets a subtle inline box highlight (light border, faint bg tint). Centered subtext 17px `#666`. Two sharp-cornered CTAs: dark filled with `→` + plain text link with `→`.
- **Metrics:** Left-aligned 48px/500 section headline. 3-col stat grid with `1px` borders. Each: 72px/600 figure + 15px label in `#666`. Pure typography, no icons.
- **Feature pillars:** 3-col, `1px` top border, 32×32 outline icon box, 15px/500 title, 14px/400 description in `#777`.
- **Social proof:** Centered `#aaa` uppercase label. Logo name row. 2-col featured quote card: left `#f7f6f4` bg, 22px/400 quote + attribution; right: painterly gradient bg with abstract CSS person silhouette.
- **Feature detail:** Pill label top-left + `Explore ›` link top-right on same row. 48px/600 H2 left-aligned. Gray subtext. Left col: feature list — inactive items are icon + text only; **active item** gets `#f0f0ee` rounded card + expanded description below. Right col: white card inside `#ebebea` rounded container, showing a product list/table UI.
- **AI break section:** Full-bleed sky gradient (`#b8d4f0` → `#fff`) + blurred white CSS cloud shapes. Centered content. Section pill + 48px H2 + body + dark pill CTA.
- **CTA block:** `background:#1a0a2e`. 60px/500 white headline. Two pills: white filled (dark text) + white outline (white text).
- **Footer:** Logo + wordmark left, links center in `#aaa`, copyright right.

## WCAG AA Accessibility

**Target:** WCAG 2.1 Level AA — minimum contrast ratios:
- **Normal text** (< 18px regular or < 14px bold): **4.5:1**
- **Large text** (≥ 18px regular or ≥ 14px bold): **3:1**

### Contrast reference table

| Text color | Background | Ratio | Status |
|---|---|---|---|
| `#ffffff` | `#0a0a0a` | 19.6:1 | ✓ Pass |
| `#e4e4e7` | `#0a0a0a` | 14.7:1 | ✓ Pass |
| `#a1a1aa` | `#0a0a0a` | 7.0:1 | ✓ Pass (body on dark) |
| `#8c8c96` | `#0a0a0a` | 5.3:1 | ✓ Pass (meta on dark) |
| `#71717a` | `#0a0a0a` | 4.2:1 | ✗ Fail — never use |
| `#52525b` | `#0a0a0a` | 2.2:1 | ✗ Fail — never use |
| `#1a1a1a` | `#f0eeeb` | 16.8:1 | ✓ Pass |
| `#666666` | `#f0eeeb` | 5.7:1 | ✓ Pass (body on warm white) |
| `#666666` | `#ffffff` | 5.7:1 | ✓ Pass (body on white) |
| `#888888` | `#ffffff` | 4.6:1 | ✓ Pass (meta on white) |
| `#aaaaaa` | `#ffffff` | 2.3:1 | ✗ Fail for normal text — large/bold only |
| `#1a0a2e` | `#ffffff` | 18.1:1 | ✓ Pass |
| `#5B5BD6` | `#f0eeeb` | 4.8:1 | ✓ Pass (accent labels) |
| `#ffffff` | `#5B5BD6` | 4.8:1 | ✓ Pass (white on indigo button) |
| `#ffffff` | `#1a0a2e` | 18.1:1 | ✓ Pass |

### Rules to follow

1. **Audit every text/bg pair before delivering.** Use the table above or calculate: `(L1 + 0.05) / (L2 + 0.05)` where L is relative luminance.
2. **Never use light grays for body text on dark backgrounds.** On `#0a0a0a`, the minimum safe gray is `#8c8c96`. Anything lighter than that fails.
3. **Never use mid-grays for body text on white.** `#999` (3.0:1) fails for normal text. Use `#666` minimum.
4. **`#aaa` on white (2.3:1) only passes for text ≥ 18px regular or ≥ 14px bold.** Use it only for large labels, legal text, or decorative elements — never body copy.
5. **Interactive elements need 3:1 contrast against adjacent colors** (button borders, focus rings, icon-only controls).
6. **Color alone must not convey meaning.** Pair color with icons, text labels, or patterns for status indicators.
7. **Focus states:** All interactive elements must have a visible focus ring — `outline: 2px solid #5B5BD6` or similar, never `outline: none` without a replacement.

## Implementation Rules

1. **Match the project's stack.** Output React/Next.js components, plain HTML, Vue, Svelte — whatever the project uses. Ask if unclear. Use the project's existing CSS approach (Tailwind, CSS modules, styled-components, etc.) rather than imposing one.

2. **No rounded corners on the Relay style.** Sharp corners everywhere — buttons, cards, code windows, hero containers. The warm off-white bg + serif type does the softening.

3. **No generic aesthetics:**
   - No purple gradient on white hero
   - No floating cards with `box-shadow`
   - No "Trusted by 10,000+ companies" with avatar rows
   - No generic blue CTA buttons
   - No Inter as the display font

4. **Hero visual:** Include a product UI mockup if the design calls for one — built in HTML/SVG (sidebar + main content, workflow diagram, data table, etc.) or left as a clearly labelled placeholder until real assets are available.

5. **Declarative, not benefit-driven copy.** Write headlines that describe a state of the world, not a feature list:
   - ✓ "The platform that never clocks out"
   - ✗ "Automate your workflows with AI"
   - ✓ "Operations that think, so your team doesn't have to"
   - ✗ "AI-powered task automation for modern teams"

6. **Section rhythm:** Alternate layout densities — full-width hero → 2-col feature → 3-col pillars → full-width CTA. Never repeat the same layout twice in a row.

7. **Typography font-weight discipline:**
   - Crimson Pro display headlines: `font-weight: 300–400` only. At large sizes (84px+) use 300 to avoid optical heaviness.
   - DM Sans hero: 700 for the Vela hero. 500–600 for section headlines. 400 for body everywhere.
   - Inter (Forge/dark): 600 for H1, 500 for H2, 400 for body.

8. **Mono fonts for UI chrome.** Navigation links, CTA buttons, section labels, and code should use Geist Mono (Relay style) or match the design system's mono font. Mono type signals precision and developer credibility.

## Page Structure (standard order)

```
Nav
Hero (H1 + subtext + CTA + product mockup)
Social proof bar (logo names, no avatars)
Feature intro (headline + body, 2-col)
Feature pillars (3-col)
Feature detail (2-col: list left, UI right)
Testimonials (2–3 col)
Metrics (3-col numbers)
CTA (full-width)
Footer
```

Not every section is required. A tight page (hero → 1 feature → metrics → CTA → footer) beats a bloated one.

## Workflow

1. **Gather inputs:** Product name · one-line description · primary buyer persona · project stack (Next.js, React, plain HTML, etc.) and CSS approach (Tailwind, CSS modules, etc.).
2. **Make design decisions** informed by the references above — palette, type pairing, layout rhythm, component style. Don't default to safe choices. Don't explain the decisions unless asked.
3. **Write copy first** (headlines, subtext, feature names, CTA). Declarative and specific, not benefit-laden.
4. **Build in section order:** nav → hero → social proof → features → CTA → footer, using the project's actual components and conventions.
5. **Audit contrast** — check every text/bg pair against the WCAG table above. Fix failures before delivering.
6. **Deliver** production-ready code in the project's stack.
